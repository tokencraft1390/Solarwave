Trust by boundaries

What Solarwave is designed to do

  • Keep small apps deliberately small.
  • Generate fresh customer-specific artifacts rather than force every buyer into one shared customer codebase.
  • Use clear tier boundaries and a maximum of five fields.
  • Separate payment verification from delivery claims.
No inflated claims

What this storefront does not promise

  • It does not claim an app is built before the order is processed.
  • It does not claim automatic provisioning is live today.
  • It does not treat an invoice or order request as paid.
  • Hosted persistence depends on the deployment environment selected for the final build.
FAQ

Before you order.

What exactly am I buying?

A bounded micro-app based on the tier and scope you submit. The current pricing is $5 Static, $10 CRUD, or $50 CRUD + Webhook.

How do I pay?

The current collection workflow uses a buyer-specific PayPal invoice after your order/spec is received. A shareable one-click PayPal payment link is not yet represented as live.

Does the $10 CRUD tier include hosting forever?

No. The tier describes the build capability. Hosted persistence needs a deployment environment with suitable durable storage; any hosting arrangement should be explicit before delivery.

Do I get source code?

The intended delivery can include the generated artifact/source where the specific order allows it. Rights, third-party dependencies, customer-provided assets and any license/assignment terms are tracked separately per delivery.

Why only five fields?

Because Solarwave is optimized for small, fast, understandable tools. If the request grows beyond that boundary, it should be rescoped rather than quietly turned into a larger project.
