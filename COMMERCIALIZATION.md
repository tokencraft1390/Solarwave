# Solarwave Commercialization — Agency Wholesale

Snapshot: 2026-10-29

## Governing objective

Convert the existing bounded micro-app factory into cleared revenue by selling white-label fulfillment capacity to agencies and consultants that already own client relationships.

Commercial sequence:

`MATCH -> PAIN -> DEMAND -> BUYER -> PRICE -> SCOPE -> PAYMENT -> VERIFY -> BUILD -> TEST -> DELIVER -> RECEIPT -> REPEAT`

## Research-backed execution plan

1. Prioritize founder-led automation/no-code/RevOps agencies already selling portals, dashboards, integrations, internal tools, and workflow systems.
2. Reach the decision maker directly with an overflow-capacity proposition, not a generic SaaS pitch.
3. Offer three fixed wholesale tiers: $350 / $650 / $1,250.
4. Use the $350 first clean scope as the proof pilot when it fits the Quick Utility boundary.
5. Ask for one real sanitized backlog item, return IN SCOPE / OUT OF SCOPE plus a fixed quote, and move directly to invoice/payment when the requirement is sufficient.
6. Do not add speculative generator capabilities. Add a missing capability only when paid demand requires it.
7. After every accepted delivery, ask for the next small client deliverable the agency would rather hand off than put back on its internal queue.

> You keep the client, branding, and markup. I handle the bounded build. Send one sanitized backlog item; I will return the normalized scope, fixed wholesale tier, inclusions, exclusions, and acceptance test. First clean pilot is $350 when it fits the Quick Utility lane.

Follow-up sequence:

- Day 5: ask whether a bounded backlog item exists now.
- Day 9: hold the first clean-scope pilot at $350.
- Day 12–14: close the loop rather than repeatedly chase.

## Buying path

`partner sees proof -> sends bounded spec -> price/exclusions shown -> invoice/payment -> payment verified -> build -> QA/evidence -> white-label delivery -> next-job CTA`

New partners prepay standard jobs. An invoice sent, verbal yes, or pending payment is not collected revenue.

## Standard production boundary

- Maximum five core fields.
- Quick Utility: no persistent CRUD.
- Working Micro-App: one role and simple persistence.
- Connected Micro-App: one bounded webhook/API integration or trigger.
- Clear acceptance test required.
- Unsupported or ambiguous work returns OUT OF SCOPE and is re-quoted.

Target external service level: same-business-day delivery for accepted standard scopes after complete inputs and verified payment. Internal production targets remain internal until proven by real paid orders.

## Primary scoreboard

- Verified partner targets.
- Personalized first touches.
- Positive replies.
- Bounded specs received.
- Same-day quotes issued.
- Paid pilots.
- Cleared wholesale revenue.
- Paid spec-to-delivery time.
- First-pass acceptance.
- Repeat orders.

Traffic, impressions, and opens are secondary unless they produce qualified buyer conversations.

## Repository and IP posture

The core factory repository is an operating/IP asset, not the customer-facing product page. Do not use the repository URL as a sales CTA. Ordinary customer delivery can include the generated artifact/source when contracted, but does not transfer the core generator, orchestration logic, validation process, prompts, or future factory rights.
